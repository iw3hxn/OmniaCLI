{{ _("1. Links to other OmniaCLI instances") | safe }}

{{ _("A link lets the users of your OmniaCLI see and operate the servers of another OmniaCLI (a customer's machine, for example) from your own pages. Below, the remote is the instance you want to reach, your instance is the one you log in to.") | safe }}

{{ _("What a link gives you") | safe }}

  • {{ _("The remote's live servers on your Dashboard, as <link> › <server>, with their load, state and Start / Stop / Restart buttons. A link that does not answer is shown as an error above the list.") | safe }}
  • {{ _("The remote's pages under /links/<link>/ on your instance, with a bar that says which instance you are on. Every action runs on the remote and is recorded there as manual: link <its name for you> (<your user>).") | safe }}
  • {{ _("You act there with the lower of your role on your instance and the link's role on the remote.") | safe }}
  • {{ _("Only users who log in with a password use links; MCP tokens do not.") | safe }}
  • {{ _("Draft servers of the remote are not listed: a link shows its active servers only.") | safe }}

{{ _("Step 1 — on the remote: create the link token (admin)") | safe }}

  1. {{ _("Open the remote's Users page, section Links.") | safe }}
  2. {{ _("Name the link after who connects, for example omniasolutions, and choose its role: user (watch, restart, start and stop Odoo), developer (also pull, update, backup, pip) or admin (everything).") | safe }}
  3. {{ _("Press Create link token and copy the token. It is shown only once; the remote keeps only its hash. If it is lost, revoke the link and create a new one.") | safe }}

{{ _("Without the web interface, on the remote's shell:") | safe }}

omniacli new-link-token omniasolutions --role developer

{{ _("It prints the token and a line to add under auth.links of the main configuration (/etc/omniacli/omniacli.yaml for the package); restart OmniaCLI afterwards (sudo systemctl restart omniacli): the main configuration is read at startup only.") | safe }}

{{ _("Step 2 — on your machine: trust the remote's certificate") | safe }}

{{ _("Your instance checks the remote's HTTPS certificate. It must name the host of the URL in its subjectAltName: the IP address when the URL uses an IP, the DNS name otherwise.") | safe }}

  • {{ _("A certificate from a public CA (Let's Encrypt and the like): nothing to do, leave the CA file empty.") | safe }}
  • {{ _("A self-signed certificate, or one from the customer's own CA: save that certificate (or the CA's) on your machine and give its path as the link's CA file.") | safe }}

{{ _("To save a self-signed certificate (replace host and port):") | safe }}

openssl s_client -connect 192.0.2.10:8443 </dev/null 2>/dev/null \
  | openssl x509 > /etc/omniacli/192.0.2.10.pem
openssl x509 -in /etc/omniacli/192.0.2.10.pem -noout -subject -ext subjectAltName -fingerprint -sha256

{{ _("Check the fingerprint against the one read on the remote itself (sudo openssl x509 -in <nginx certificate> -noout -fingerprint -sha256): what openssl s_client downloads is whatever answers on that address. The file must be readable by the user that runs OmniaCLI (omniacli for the package).") | safe }}

{{ _("Step 3 — on your instance: add the link (admin)") | safe }}

{{ _("Open the Links page and fill in the last row:") | safe }}

{{ _("Field") | safe }}{{ _("Value") | safe }}
{{ _("Link") | safe }}{{ _("a name: letters, digits, . _ -. It becomes part of the URLs (/links/<name>/), so the customer's name is a good choice.") | safe }}
URL{{ _("the remote's address, https://host[:port][/path], for example https://192.0.2.10:8443. An http:// URL is accepted but the token travels in clear: use it only through a VPN or an SSH tunnel.") | safe }}
Token{{ _("the token of step 1.") | safe }}
{{ _("CA file") | safe }}{{ _("empty for a public CA, otherwise the path of step 2.") | safe }}

{{ _("Press Add link, then Test link: it shows the remote's OmniaCLI version and the role you get there. The links and their tokens are saved in the links file of your instance, readable by its owner only.") | safe }}

{{ _("2. The MCP server") | safe }}

{{ _("OmniaCLI serves an MCP endpoint (streamable HTTP) for AI clients such as Claude Code:") | safe }}

{{ base_url }}/mcp

{{ _("A client authenticates with a bearer token, never with a user's password. Every call is listed in the Access log (Users page, admins), with the token, the address and the tool.") | safe }}

{{ _("Token roles") | safe }}

{{ _("Role") | safe }}{{ _("The client may") | safe }}
{{ _("user") | safe }}{{ _("read: list_servers, server_status, read_log, list_jobs, get_job, pending_updates, dev_setup") | safe }}
{{ _("developer") | safe }}{{ _("also update_test (git pull, update of the changed modules and restart of a test instance) and backup_test, and download backups") | safe }}
{{ _("admin") | safe }}{{ _("also backup and list_backups of any instance (production too), read_server (a server's whole configuration) and add_draft_server (a new server, always a draft). With an admin token, dev_setup, backup and list_backups also reach the draft servers.") | safe }}

{{ _("A client sees only the tools of its role. A token saved without a role (before roles existed) is a developer. The role can be changed at any time on the Users page; it applies to the next call. No token makes a draft server live: that is Test & activate on the web interface, by an admin.") | safe }}

{{ _("Step 1 — create the token (admin)") | safe }}

  1. {{ _("Open the Users page, section MCP tokens.") | safe }}
  2. {{ _("Name it after the client, for example dev-laptop, choose its role and press Create MCP token.") | safe }}
  3. {{ _("Copy the token: a string of about 43 letters, digits, - and _. It is shown only once.") | safe }}

{{ _("The sha256$… value in the users file is the token's hash, not the token: the token cannot be recovered from it, and a client that sends it is refused. A lost token is revoked and created again.") | safe }}

{{ _("Without the web interface, on the server's shell:") | safe }}

omniacli new-token dev-laptop --role admin

{{ _("It prints the token and a line to add under auth.tokens of the main configuration; restart OmniaCLI afterwards.") | safe }}

{{ _("Step 2 — add the server to the client") | safe }}

{{ _("In Claude Code, on the machine of the client:") | safe }}

claude mcp add --scope user --transport http omniacli {{ base_url }}/mcp \
  --header "Authorization: Bearer <token>"
  • {{ _("--scope user makes it available in every project; without it, it is registered for the folder the command runs in only.") | safe }}
  • {{ _("To replace it: claude mcp remove omniacli (in the same scope), then add it again.") | safe }}
  • {{ _("Check with claude mcp list, or /mcp inside a session.") | safe }}
  • {{ _("Without --header, Claude Code connects with OAuth: /mcp in Claude Code opens the login of OmniaCLI, and no token is needed.") }}
  • {{ _("claude.ai, ChatGPT and the connectors of Claude Desktop connect with OAuth to this same URL, from the internet over https: the Users page says how, under How to connect… of a token.") }}
  • {{ _("Over HTTPS with a self-signed certificate, the client must trust that certificate as well (step 2 of the links); how depends on the client.") | safe }}

{{ _("Downloading a backup") | safe }}

{{ _("backup, backup_test and list_backups answer with a download path. The zip (database dump and filestore) is an HTTP GET on that path with the same header:") | safe }}

curl -fH "Authorization: Bearer <token>" -o backup.zip \
  {{ base_url }}/backups/<server>/<role>/<file>.zip

{{ _("Add --cacert <certificate> for a self-signed certificate.") | safe }}

{{ _("3. Adding a server: the fields and the configurations") | safe }}

{{ _("The Servers page (admins) lists every server, live or draft, with New server, Edit, Clone (the configuration only: no database, no files), Set to draft and Delete (the configuration only: databases and files are not touched). A server is a name and up to two instances, production and test: tick the ones it has, at least one.") | safe }}

{{ _("Draft and live") | safe }}

  • {{ _("Save as draft saves without any check, also incomplete. A draft is not live: it is not on the Dashboard, has no actions and no auto update.") | safe }}
  • {{ _("Save, test & activate (or Test & activate on the Servers page) runs the checks: config and paths readable, click-odoo scripts in the venv and Odoo importable, the database reachable, every repository on its branch without local changes, the service found, sudo allowed, production and test on separate databases and working copies, the backup folder writable. If they all pass, the server goes live; the dialog lists each check. A database that does not exist yet, or an empty one, is only a warning: Start and Restart refuse it until a backup is restored with Restore (admin): a zip from this computer, or one of the instance's backups; a production needs its database name typed.") | safe }} {{ _("For Odoo, Restore also takes a plain SQL dump (pg_dump --format=plain, of any name): it replaces only the database, the filestore stays as it is; neutralized by Odoo if asked, with a new database uuid and web.base.url set to the instance's address.") | safe }}
  • {{ _("On a live server, Test & save saves the change only if every check passes, otherwise the server stays as it was; Save as draft takes it offline.") | safe }}
  • {{ _("A server with a running job cannot be edited or deleted. Every save keeps the previous servers file as .bak.") | safe }}

{{ _("Docker Compose: who may change the project is root") | safe }}

{{ _("Docker runs as root what a project's files say: whoever may change them may mount the whole machine into a container (one compose.override.yaml is enough) and is root through every up -d. So OmniaCLI never runs docker itself: it runs omniacli compose-helper <folder> <action>, which takes a fixed list of actions and, as root, refuses a project that the user who called sudo could change:") | safe }}

  • {{ _("the project's folder, and every folder above it up to / (one that may be written may put another folder in its place; a sticky one, as /tmp, only when the folder is that user's), must not be writable by that user; the folder may not be reached through a symbolic link;") | safe }}
  • {{ _("nor compose.yaml, compose.yml, docker-compose.yaml, docker-compose.yml, their .override.yaml/.override.yml (docker compose reads them by itself) and .env; none may be a symbolic link;") | safe }}
  • {{ _(".env may not set COMPOSE_FILE, COMPOSE_PATH_SEPARATOR or COMPOSE_PROJECT_DIRECTORY, which make docker compose read other files.") | safe }}

{{ _("A file is writable by its owner (who may change its mode) and through the group or other write bit that applies; ACLs are not read. The Service check makes the same checks as OmniaCLI's user and prints, for each problem, the command that fixes it. Secure a project so:") | safe }}

chown -R root: /srv/odooplm-19
chmod -R go-w /srv/odooplm-19

{{ _("The folders the project mounts (./config, ./addons-extra...) are not checked: who writes them controls Odoo inside its container, not the machine.") | safe }}

{{ _("Docker Compose: the log") | safe }}

{{ _("An Odoo in a container writes its log to its output, which docker keeps: the Log page, the read_log tool and the Log check read it with docker compose logs of the service the type names (for Odoo, its service), through the helper: the last 300 lines, then every 2 seconds the lines written since the last one read, by their time. How much log there is, docker decides: with its default driver (json-file) and no limit the log grows for ever, and when its container is made again (a changed .env or image, down) the lines before are gone; the page keeps showing the ones it has and goes on with the new container's. Limit it in the compose file:") | safe }}

services:
  odoo:
    logging:
      options:
        max-size: "50m"
        max-file: "5"
